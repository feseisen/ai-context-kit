# ai-context-kit — 自分専用の「外部脳」を作るキット

AIとの会話を自動で取り込み、そこから**判断基準・知識・案件の状況**を抽出して、以後すべてのセッションの前提として読ませるための土台です。

**あなた個人に関する中身は空です。** 構造とルールだけが入っていて、判断基準や会話ログはあなたが埋めます。

**例外が1つあります。**`areas/practice/` には、作者が生成AIと組むうちに得た**原則**が入っています（「何を大事にすべきか、それはなぜか、どう作って運用するか」）。これは作者個人のことではなく、誰が使っても成り立つ骨組みの知見として書いてあるものです。入口は [`areas/practice/README.md`](areas/practice/README.md)。

## 対応環境

**特定のAIや契約プランに合わせて作ってはいません**。文章の部分はどの生成AIにも渡せます。ツールの部分だけが、特定の環境を前提にしています。

| 部分 | 使える環境 | 前提になっているもの |
|---|---|---|
| 文章（`CONTEXT.md`、`AGENTS.md`、`areas/` の原則と雛形） | どの生成AIでも（Claude の各プラン、ChatGPT など）。貼るか、ファイルとして読ませる | なし |
| 自動で読ませる入口 | Claude Code は `CLAUDE.md` を、`AGENTS.md` に対応したツールはそちらを読む | そのツールがフォルダのファイルを読めること |
| バージョン管理（`.githooks/`、`tools/auto-sync.py`） | git が使える環境ならどこでも | git と Python |
| 会話の取り込み（`tools/import-claude-sessions.py`） | Claude Code | Claude Code が手元に残す会話記録 |
| 会話の取り込み（`tools/import-claude-ai-export.py`） | claude.ai | claude.ai のデータのエクスポート |
| 一括セットアップ（`tools/setup.py`）とフック | Claude Code | `~/.claude/` の設定ファイル |

**作者が実際に動かしたのは、個人の端末の Claude Code だけです**。それ以外の環境で使えるかどうかは、書かれている前提から見込んだだけで、確かめていません。
ほかのAIの会話を取り込むツールはまだありません。取り込みは「会話を `raw/` に置く」ことなので、会話をエクスポートできる環境なら、エクスポートした会話を同じ形で `raw/` に置けます。

## 何を解決するのか

AIは望むとおりには動きません。その原因を「指示の書き方」ではなく**前提の欠落**に求めると、解決策はプロンプトの工夫ではなく**文脈（前提となる情報）を渡すこと**になります。

目指す状態は、**前提が共有されていて、いちいち説明しなくても意図が通る**こと。どれだけ多くの仕事を任せられるかの話ではありません。

そのために必要なのは2つです。

1. **自分が触れる情報を取り込む**
2. **AIが扱える形に加工する** ← 取り込むだけでは足りない、というのが肝

このキットは、そのうち「**AIとの会話」の取り込みと加工**を担当します。

## 設計の肝

### 1. 生データと加工済みを両方持つ

```
raw/     未加工の会話ログ（原文のまま。手で編集しない）
areas/   そこから抽出した加工済みの知識
```

抽象化した層を常用しつつ、必要なときは生データまで降ります。**二者択一にしません。**

抽出したからといって生データが不要になるわけではありません。「AIが常に知っておくべきこと」は一部で、必要に応じて元を読みに行く場面が必ず出ます。

### 2. 同じ話題が2箇所にあってよいのは、抽象度が違うときだけ

**上の層は「入口とパス」を持ち、下の層が「事実」を持ちます。**
上の層に事実を書き写すと、書き写した内容はその瞬間から古くなり始めます。

これは Single Source of Truth の原則であり、同時に Anthropic が [context engineering の記事](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)で書いている **just-in-time retrieval**（ファイルのパスのような短い手がかりだけを持たせ、必要になった時点で読みに行かせる）と同じ考え方です。

### 3. 人は毎回判断する役ではなく、AIが判断をすり合わせる相手

| 工程 | 誰が | 人の関与 |
|---|---|---|
| 取り込み | 機械（フック） | **無し** |
| 抽出・抽象化 | **AI** | **無し**（AIが判断して書く） |
| 検証・修正 | 人 | **問われたときに答える／後から訂正する** |

毎回チェックする運用は続きません。**AIが判断して書き、人は後から直す**方が回ります。
ただしAI側は、**確信が持てないとき・抽象化の粒度に迷うときは黙って決めずに問う**こと。その問答の積み重ねが次の抽出精度を上げます。

### 4. 捨てる方が多い

会話ログのうち残すのは**実測で 2.1%** でした。

| 内訳 | 割合 |
|---|---|
| スクリーンショット | 78% |
| ツールの入出力 | 20% |
| **実際の発言** | **2.4%** |

| 残すもの | 捨てるもの |
|---|---|
| 人間とAIの**発言（原文のまま）** | ツールの出力（コマンド結果、読んだファイルの中身） |
| ツール操作の**1行の記録**（何をしたか） | 書いたコードやファイルの本文 |
| セッションのタイトル・日時・プロジェクト | スクリーンショット画像 |
| | システムが会話に差し込む注記 |

書いたコードを残さないのは、**それがリポジトリ側に既にあり、なくてもAIが作り直せるから**です。一方で「なぜその作りにしたか」は会話にしか残りません。そちらを優先します。

**目的はアーカイブではなく、文脈の継承です。**

副次効果として、ツールの出力を捨てることで**秘密情報が混入する経路の大半が最初から塞がります。**

## 構成

```
README.md          このファイル。人間向けの案内
CLAUDE.md          Claude Code が自動で読む入口。AGENTS.md へ案内する
AGENTS.md          AIエージェント向けの振る舞い規定（★最重要ファイル）
SKILL.md           スキルとして読み込ませる場合の入口
setup.bat / setup.sh  一括セットアップ（試作）。tools/setup.py を呼ぶだけ
index.md           全エントリの目次（AIが最初に見る）
log.md             いつ何を追加・更新したかの記録
.githooks/
  pre-commit         秘密情報の誤コミットを防ぐGitフック
tools/
  import-claude-sessions.py    Claude Code の会話ログを取り込む
  import-claude-ai-export.py   Claude.ai のデータエクスポートを取り込む
  auto-sync.py                 フックから呼ばれ、取り込み・コミット・プッシュまで行う
  claude-settings-hook.json    自動化のための設定の雛形
  setup.py                     手順1・4・5をまとめて済ませる（試作。--dry-run あり）
raw/               未加工の元データ
  sessions/          AIとの会話ログ（自動生成）
  memory/            AIのメモリファイルのコピー
  attachments/       画像から読み取った情報の書き起こし
areas/             継続的な関心領域ごとの「加工済み」の知識
  self/              本人の思考様式・判断基準・口調（★中核。個人の層）
  practice/          生成AIと組むときの原則（★骨組みの層。人に渡せるのはここだけ。作者の原則入り）
  dev-environment/   開発環境の設定・ツールの意思決定ログ
  people/            人間関係マップ（組織図に相当する構造）
  glossary/          用語辞典（社内用語辞典に相当する構造）
  threads/           継続中の案件・やり取りの履歴（取引履歴に相当する構造）
```

各 `areas/` フォルダには `_template.md` が入っています。コピーして使ってください。
テンプレートを別フォルダにまとめていないのは、**使う場所の隣に置いたほうが見つけやすいから**です。

`areas/` のフォルダ名が業務っぽいのは意図的です。**組織の知識管理に必要な構造を、個人の情報で先に練習しておく**という設計になっています。私用の端末で業務情報は扱えませんが、構造だけは先に作れます。

## 始め方

### いちばん短い始め方（3ステップ）

> **試作中です**。この一括セットアップを正式にキットに含めるかは、まだ決まっていません。

1. ZIP を展開し、フォルダの名前を好きなもの（例: `my-brain`）に変える。置き場所は、git で管理しているフォルダの**外**にする
2. セットアップを実行する
   - Windows: フォルダの中の `setup.bat` をダブルクリック
   - macOS・Linux: そのフォルダで `sh setup.sh`
3. Claude Code を、そのフォルダで開く。最初の仕事は `areas/self/vision.md` を書くこと（下の手順2）

セットアップがやるのは、下の手順1・4・5と、`git init`・空フォルダの用意です。
**キットの外にある2つのファイル**（`~/.claude/CLAUDE.md` と `~/.claude/settings.json`）は、
書く前に変更点を見せて `y/N` で聞き、元のファイルを同じ場所にバックアップしてから書きます。既にある設定は消しません。
何度実行しても同じ結果になります。書き込まずに、やることだけ先に見たいときは `setup.bat --dry-run`（または `sh setup.sh --dry-run`）。
ネットワークには接続しません。push 先（手順0の private リポジトリ）は作りません。

以下は、セットアップが中で何をしているかと、手でやる場合の手順です。

### 0. 自分用のリポジトリは private にする（最重要）

**このリポジトリを fork して、そのまま使わないでください。**

このキットは**あなたの会話ログを溜めるための仕組み**です。public のまま使うと、
取り込まれた会話が**そのまま全世界に公開されます**。自動同期を有効にしていれば、
あなたが気づかないうちに、AIの応答が終わるたびに push されます。

正しい始め方は、**中身だけをコピーして、自分の private リポジトリを新しく作る**ことです。

```
# fork や clone ではなく、中身をコピーして自分のリポジトリを作る
git clone --depth 1 https://github.com/feseisen/ai-context-kit my-brain
cd my-brain
rm -rf .git
git init
# ここで GitHub に private リポジトリを作り、remote に設定する
```

**`rm -rf .git` を忘れないこと。** 元の履歴を引き継いだまま push すると、
リモートの設定を間違えたときに気づきにくくなります。

**ZIP で受け取った場合、または Windows の PowerShell の場合**は、上の代わりにこうします。
ZIP には `.git` が入っていないので、消す手順は要りません。

1. ZIP を展開し、フォルダの名前を好きなもの（例: `my-brain`）に変える
   （GitHub のページからなら「Code」→「Download ZIP」。ログインは要りません）
2. そのフォルダで `git init` を実行する

PowerShell では `rm -rf .git` は動きません。clone した場合は
`Remove-Item -Recurse -Force .git` を使います。

remote（push 先）が無くても、手順1〜5は進められます。
その場合、自動同期（手順4）はコミットまでして、push だけ失敗し続けます（止まりはしません）。

### 1. フックを有効にする

```
git config core.hooksPath .githooks
```

`.githooks/pre-commit` が、コミット前に「追加された行」だけを走査し、APIキー・トークン・秘密鍵らしき文字列を見つけたらコミットを中断します。**Git のフック設定はクローンに引き継がれないため、環境ごとにこのコマンドが必要です。**

GitHub の push protection が使えるプランならそちらも併用してください。無料プランの private リポジトリでは使えないため、このフックはその代替です。

### 2. `areas/self/vision.md` を書く

**ここが中核です**。最初の1ファイルはこれで、しかも**そもそもの目的から書きます**。

> 自分は何のためにこれをやるのか。この外部脳で何がどうなってほしいのか。
> 作ったものをどこまで広げるのか（自分の手元だけか、別の環境へ持っていくのか、人に渡すのか）。
> どういう状態になったら成功なのか。

これを書かずに会話ログだけ溜めても、AIは何を抽出すべきか判断できません。
うまく言葉にならなければ、**AIに喋って書き起こさせる**のが早いです（このキット自体、その方法で作られています）。

**優先度をここに書き留めないこと。**「AとBが大事」と書くと、状況が変わっても気づけません。書くのは**目的から優先度を導くための判断基準**で、当てはめた結果は「今日の時点ではこうなる」という例として添えます。

### 3. 会話ログを取り込む

```
python tools/import-claude-sessions.py
```

何度実行しても同じファイルが更新されるだけなので、気づいたときに実行して構いません。

- `python` で動かなければ `python3`（macOS・Linux）か `py`（Windows）に読み替えてください
- Claude Code をまだ一度も使っていないと `no session files found under ...` と出て終わります。
  不具合ではありません。Claude Code で会話してから、もう一度実行してください
- 書き込まずに結果だけ見たいときは `--dry-run` を付けます
- Claude.ai（ブラウザ版）の会話は自動では取れません。エクスポートしたデータ（ZIP）を展開し、そのフォルダを指定して実行します:
  `python tools/import-claude-ai-export.py <展開したフォルダ>`

### 4. 自動化する（任意）

`tools/claude-settings-hook.json` の内容を Claude Code の設定（`~/.claude/settings.json`）にマージすると、**応答が一区切りついたタイミングで自動的に取り込み・コミット・プッシュ**されます。

**マージする前に、雛形の `<このリポジトリの絶対パス>` を2か所とも書き換えてください。**
フックはどのフォルダのセッションからも呼ばれるので、相対パスでは動きません。
Windows でもパスの区切り文字は `/` で書けます（例: `D:/work/my-brain`）。`python` の読み替えも手順3と同じです。
試しに1回だけ動かすなら `python tools/auto-sync.py --verbose` で、何をしたかが表示されます。

- フックが動くのは `Stop`（応答の終わり）と `SessionEnd`（セッションの終わり）
- **全プロジェクトのセッションが対象。** どのフォルダで作業していてもここに集まる
- **`raw/` 配下しかコミットしない**ので、作業中の他の変更を巻き込まない
- 変更がなければ何もしない。失敗してもセッションは止まらない

### 5. 全セッションの前提にする

全プロジェクト共通の指示ファイル（Claude Code なら `~/.claude/CLAUDE.md`）から、このリポジトリを**判断基準の正本（よりどころ**）として参照させます。これをやって初めて「いちいち説明しなくても通じる」状態になります。

書く中身は、たとえばこれだけで足ります（パスは自分のものに）。

```
判断基準の正本は <このリポジトリの絶対パス> にある。
作業を始める前に、そこの CLAUDE.md → AGENTS.md → areas/self/vision.md → index.md の順に読む。
```

このリポジトリのフォルダで直接セッションを始めたときは、同梱の `CLAUDE.md` が自動で読まれ、同じ入口へ案内されます。

詳しくは `AGENTS.md` の 0.6 を読んでください。

## 破綻する条件を先に決めてある

この仕組みは `index.md` を頼りにAIが読みに行く方式で、全文検索の仕組みもベクトル検索も持ちません。**小さいうちは足りますが、いずれ破綻します。**

`AGENTS.md` の 0.9 に、見直しのトリガー（`areas/` が50ファイル、`index.md` が150行、「探したが見つからなかった」が月2回）と、そのときの選択肢を書いてあります。

**壊れてから考えるのではなく、壊れる条件を先に書いておく**という方針です。

## これは仮説です

正解が確立している領域ではありません。`AGENTS.md` の各ルールには、**検証の機会と、外れたときにどうするか**を併記してあります。

うまくいかなかった点があれば、Issue で教えてもらえると助かります。
