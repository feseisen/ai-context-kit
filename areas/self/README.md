# self/（本人の思考様式・人物像）

このリポジトリの**中核**にあたるフォルダ。他の `areas/` が「知識」を置く場所なのに対し、ここは「**その知識をどう扱う人間なのか**」を置く場所。

## なぜこの領域があるか

目的は、本人のクローンAIを作ること。表層的な模倣ではなく、実際に判断の代わりが務まるもの。

構成要素は2つに分かれる。

| 要素 | 中身 | 優先度 |
|---|---|---|
| **能力** | 思考様式、判断基準、暗黙知、何を重視し何を嫌うか | **こちらを重視** |
| **キャラクター性** | 口調、一人称、言い回し、話し方の癖 | 最終的には盛り込みたい |

**順序が重要。** 能力が伴わないキャラクター性だけの模倣は、ただの物真似になる。
このフォルダも、**思考様式を先に厚くし、口調は後から重ねる**という順で育てる。

## 構成

```
self/
├── vision.md                目指している状態（★最初に書く。すべての幹）
├── thinking-principles.md   思考様式・判断基準（＝能力の核）
├── working-with-ai.md       AIとの働き方の好み・常設指示
└── voice.md                 口調・言い回し（＝キャラクター性）
```

## 育て方

`raw/sessions/` に溜まる会話ログが材料。そこから次を拾って集約する。

- **本人が繰り返し言っていること**
- **強い言葉で指示していること**
- **訂正・却下したこと** ← これが一番効く

一度きりの発言より、**複数のセッションをまたいで繰り返される判断**のほうが価値が高い。
逆に「これは今回に限らず覚えておいて」と明示された指示は、1回でも最優先で記録する。

**引用は原文のまま残す。** 要約すると、判断のニュアンスが最初に落ちる。

## vision.md を最初に書く

ここが空のまま会話ログだけ溜めても、AIは何を抽出すべきか判断できない。

書くこと:

- 何のためにこれをやるのか
- どうなったら成功なのか
- なぜ今それが必要だと思ったのか（きっかけになった実感）
- 分かっているハードルは何か（解けていなくてよい）

**うまく言葉にならなくてよい。** AIに喋って書き起こさせるのが早い。
その際、AI側には「**要約せず、原文の言い回しを残す**」よう指示すること。
