## 原則

**第三者が見られる状態を作る操作だけは、必ず人間が行う**。そこに至るまではAIが全部やってよい。溜まった差分は、まとめて一度に見られる形で出す。

## なぜ

自律的に進ませるほど、**取り消せる操作と取り消せない操作の間に、線を一本だけ引く**ことが効いてくる。公開は取り消せない（消しても見た人の記憶とキャッシュは消えない）。逆に言えば、公開さえ握っておけば、その手前は全部間違えてよい。

そして**人間は細切れの承認を捌けない**。1件ずつ「これを出していいですか」と聞かれると、判断が雑になるか、溜まって止まるかのどちらかになる。承認の回数を減らし、1回あたりの情報量を上げる方が、実際には慎重になる。

## どう使う

- 公開に至る操作を、仕組みの側で**禁止しておく**（口約束にしない）。AIが判断を誤っても手が届かない形にする
- 公開版を作る仕組みと、公開する仕組みを分ける。作る方は何度実行してもよく、出す方は人間の操作が要る
- 公開版は**毎回まるごと作り直す**。手で直せてしまうと「複製を直す」運用が成立し、正本と食い違う
- 複製するファイルは**許可リスト**で指定する。除外リスト方式にすると、正本に増えた新しいファイルが知らないうちに公開される
- 「今公開されているもの」との差は、公開版そのものではなく**別の記録**（公開時に取ったハッシュ値）と突き合わせて出す。作った公開版を、いま公開されているものの記録として扱わない
- **差分があること自体は許可ではない**。承認は1回の公開にだけ効き、次の差分には効かない

### 人間が行うのは外に出す操作だけ。承認を増やすと、それ以外の作業まで止まる

境界を一本引くことの裏側は、**その一本以外では人間を待たない**という約束になる。ここが崩れると、原則そのものが効かなくなる。細かい承認が増えるほど、本当に見てほしい操作も同じ扱いで流される。

線は「危なそうか」ではなく、**取り消せるか・その人にしかできないか**で引く。この環境で置いている4つはこうなっている。

| 先に許可を取るもの | なぜ |
|---|---|
| 外に出るもの（公開、外部への送信） | 取り消せない |
| 取り消せない削除、履歴の書き換え | 取り消せない |
| ひとりでに動き続けるもの（定期実行を足す・変える） | **置いた後は人がいなくても動き続ける**。一度の承認が将来の全部に効いてしまう |
| その人の端末で手を動かす必要があるもの | こちらから手が届かない |

3つ目が見落とされやすい。ひとりでに動くものは、**足した瞬間には何も起きない**ので危険に見えない。効きはじめるのは、誰も見ていないときになる。

そして、**この4つの外にあるものは全部やる**。変更を PR として出して記録に残すのはよいが、**人が押すのを待って止まらない**。待ちを許すと、自律実行の成果は「人が見た回数」で頭打ちになり、その人が見ていない時間が丸ごと無駄になる（→ [autonomy-and-decision-log](autonomy-and-decision-log.md)、[visible-state-over-notification](visible-state-over-notification.md)）。

## 根拠

### この環境で起きたこと

- 2026-09-21 — 作者が、**自分の確認を待って作業が止まらないようにしてほしい**として、マージと GitHub の更新をAIに任せ、先に許可を取るのは上の4つだけと線を引き直した。**記録としての PR は出してよく、待つことだけが禁じられている**（原文は作者個人の記録。キットには入っていない）
- 2026-09-17 — 作者の判断として、公開は一括で見てから決めたい（細切れには出せない）ことが明示された
- 2026-09-16 — 一度公開した後、同日に一部を下書きに戻した。**出してから直す運用はやはり成立しない**
- 2026-09-20 — 差分が2つの公開先で6ファイル溜まった状態で、押す手前まで全部（差分の中身、規則との突き合わせ、校正）を用意して止めてある
- 継続中 — 許可リストがフォルダ単位になっている箇所では、新しく増えたファイルが自動的に公開対象に入ってしまう。**許可リストの粒度が細かいほど安全**ということが、ここに表れている

### 外部の知見

- 人が承認のループに入る設計（human-in-the-loop）の定石 — **全部を確認させるのではなく、取り消せない操作にだけ関門を置く**。確認の数が増えるほど確認は形骸化する（[Human-in-the-loop in AI workflows](https://zapier.com/blog/human-in-the-loop/) ほか）

## 見直す条件

- 溜めた差分が大きくなりすぎて本人が見きれなくなったら、溜める単位を切り直す
- 承認のボタンが、実際には内容を見ずに押されるようになったら、出し方（見せる形）が悪い
