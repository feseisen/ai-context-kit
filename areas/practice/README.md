# practice/（生成AIと組むときの原則）★骨組みの層

生成AIを使ううちに分かった「**何を大事にすべきか、それはなぜか、具体的にはどう作って運用するか**」を1件1ファイルで溜める場所です。思いついたことではなく、**自分の環境で実際に起きたこと**か、**外から確かめた知見**のどちらかを根拠に持つものだけを置きます。

**このフォルダだけは、中身が入っています。**作者が自分の環境で生成AIと組むうちに得た原則を、そのまま入れてあります（一覧は下の「入っている原則」）。キットのほかの場所（`areas/self/` など）は空の雛形です。

原則は、作者の手元の正本から作ったものです。多くは、作者の口述の引用・生活時間・非公開の案件名だけを言い換えた版で、**主張と根拠の筋は変えていません**（書き換えた版は、先頭のコメントにもとにした正本を書いてあります）。読むときに知っておくとよいことが4つあります。

- 文中の「**本人**」は作者、「**この環境**」は作者の環境のことです。根拠の日付や数字も、作者の環境で起きたことです
- 「**（個人の記録。キットには入っていない）**」「**（キットには入っていない）**」は、元の環境では作者の個人の層（判断基準・会話の原文など）や、キットに入れていない道具を指していた箇所です。**リンクだけを外し、本文はそのまま残しています**
- 根拠に出てくる役の名前は、作者の環境での呼び名です。**どれも特定の製品の機能名ではありません。**
  - 「**受付役**」— 人からの話を最初に受けて、どの作業セッションに回すかを決める窓口のAIセッション（→ [agent-front-door](agent-front-door.md)）
  - 「**指揮役**」— 以前、受付役の前に置いていた、配分と見回りをひとりでこなす常駐のAIセッション。途中で退役している
  - 「**スレッド**」「**担当**」— 1つの話題・案件を受け持って並行して動く作業セッション
  - 「**5時間枠**」「**1週間枠（7日枠）**」— 作者が使っている生成AIの定額契約の利用上限。短い時間枠と長い時間枠の2本立てで、使用率（%）で示される
  - 「**本人のPC**」と「**クラウド**」— 作者の手元の端末で動くものと、サーバ側で動くAIセッション。測れるもの・触れるものが違う
- 根拠に出てくる `usage-autopilot` などは、作者の別の取り組みの名前です。そのうち公開しているものは [usage-autopilot-public](https://github.com/feseisen/usage-autopilot-public) にあります。`tools/calibration.py` など一部の道具はそちらにありますが、根拠に書かれたファイルの多くは、どこにも公開されていない作者の手元の記録です。**作者の学びの記録（番号付きの項の一覧）を指していた箇所は、指す先を外し、その項が示したことを本文に短く書き足してあります**

自分で使うときは、**ここにある原則を土台に、自分の環境で起きたことを「根拠」に足していってください。**合わないと分かったものは消して構いません。見直す条件は各ファイルの末尾にあります。

## なぜここが分かれているか

この外部脳の中身には、**人に渡せるもの**と**渡さないもの**があります。

| | 置き場 | 何が入るか | 渡せるか |
|---|---|---|---|
| **骨組みの層** | `areas/practice/`（ここ） | 誰が使っても成り立つ原則 | **渡せる** |
| **個人の層** | [`areas/self/`](../self/) ほか `areas/` の各領域、`raw/` | 本人の判断基準・口調・癖・発言の原文 | 自分の手元まで |

**ここに本人固有の事情を書かないこと。**書きたくなったら `areas/self/` の該当ファイルへのリンクに置き換えます。こうしておくと、渡すときに「このフォルダを入れて、あのフォルダは入れない」だけで分離が済みます。複製を作って個人の情報を消して回る運用は、必ず消し漏れます。

## どこから来て、どこへ行くか

```
各案件のリポジトリ            このフォルダ              渡す先
（実測・事実・その案件固有） →  （一般化できた知見）  →  別の環境 / 他人 / 組織の外
```

- 案件の中で測った生の数字や出来事は、**その案件のリポジトリに残す**のが先
- そのうち**他の道具・他の人にも効く形に書き直せたものだけ**が、ここに上がってくる
- 上がってきても、案件側の記録は消さない。抽象度が違うので重複ではない（→ [AGENTS.md](../../AGENTS.md) 0.8）

**特定の道具やベンダーの中にだけ知見を溜めないこと。**ここに書けば、その道具が無くなっても残ります。

## 1件の型

`_template.md` をコピーして作ります。見出しは変えないでください（後から機械的に拾えなくなるため）。

- **原則** — 一行。これだけ読めば何を守るかが分かること
- **なぜ** — 守らないと何が起きるか
- **どう使う** — 具体的な設計・運用。読んだ人がその場で真似できる粒度で
- **根拠** — 「自分の環境で起きたこと」と「外の知見」の**どちらか一方は必ず埋める**。両方空なら、それはまだ原則ではなく思いつきです
- **見直す条件** — 何が起きたらこの原則を疑うか。確信度が `仮説` のものには必ず書く

**外の知見は、実際に開いて確かめてから書くこと。**開けなかったものは根拠に書かず、「確かめられていない」と書きます。数字は出典ごとに食い違うことがあるので、**食い違いは揃えずにそのまま残します**。

確信度（フロントマターの `confidence`）は3段階です。**`仮説` のまま置いておいてよい**、というのがこの型の要点です。固まるまで書かないと、根拠になる出来事の方が先に忘れられます。

| | 意味 |
|---|---|
| `仮説` | 一度うまくいった。または外の知見に沿っているだけ |
| `検証中` | 反証を探している最中。見直す条件を決めてある |
| `定着` | 違う場面で繰り返し効いた。破ったときに実害が出たことがある |

フロントマターの `layer: 骨組み` は固定です。このフォルダに個人の層は置きません。

## 増やし方

1. `_template.md` をコピーして `areas/practice/<英語の短い名前>.md` を作る
2. `index.md` と `log.md` を同じコミットで更新する（[AGENTS.md](../../AGENTS.md) 1.）

**既存のファイルに追記できないかを先に見ること。**同じ原則を別の名前で2つ作ると、どちらも育ちません。

## 未解決のものは捨てない

答えが出ていない問いは `OPEN-QUESTIONS.md` に残します。1件につき **問い / なぜ未解決か / 今の暫定 / 何が分かれば決まるか**。原則にならなかった問いこそ、後から効いてきます。

作者の `OPEN-QUESTIONS.md` は、このキットには入れていません。まだ原則になっていない問いで、作者個人の事情が濃いためです。原則の中でそれを指していた箇所は、リンクを外してあります。自分の分は、このフォルダに新しく作ってください。
